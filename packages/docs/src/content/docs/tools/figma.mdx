The Figma export turns every theme into files Figma can import, from the same tokens as the CSS. Colours, spacing, radii, borders, type and shadows keep the names they have in code, so a designer's `surface/card` is a developer's `--surface-card`.

There are two ways in. Pick one per file:

- **Figma variables**, with the free Export/Import Variables plugin by Honza Toman. Variables you bind straight to fills, strokes, gaps and padding.
- **Tokens Studio**, with the Tokens Studio for Figma plugin. Tokens you apply through the plugin, and the only route to the library's text styles and shadow effects.

## 1. Get the files

The files come from the [Token Designer](/docs/tools/)'s Figma export, which builds them from your theme each time. The Token Designer isn't released yet, so this page describes what the export makes and how to use it.

## 2. Find your theme

| Folder | What it holds |
| :--- | :--- |
| `native-variables/`, `tokens-studio/` | The default theme |
| `themes/<name>/` | One other theme or sub-brand, complete on its own |
| `themes/<name>-modes/` | A theme and all its sub-brands together, a mode per brand |

Every theme's folder has both forms: `native-variables/` and `tokens-studio/`. A sub-brand's own folder is complete, with its parent's tokens included, so it imports without the parent.

## 3. Choose the set for your plan

Figma limits how many modes a variable collection can have: 1 on Starter, 10 on Professional, 20 on Organization and 40 on Enterprise.

| You want | Import | Plan |
| :--- | :--- | :--- |
| One brand, one mode: light, fixed type | `dfh-unified.json` | Any, including Starter |
| One brand, with light and dark, font sizing, spacing and pointer modes | `01-color.json`, `02-structure.json`, `03-font-sizing.json`, `04-spacing.json`, `05-pointer.json` | Professional and above |
| A brand and its sub-brands, switchable on any frame | The same five files from `<name>-modes/` | Its README says which plan; usually Organization |

The `-modes` README counts the modes in each collection and names the smallest plan that holds them. When your plan is too small, import each brand's own folder into its own file instead.

## 4a. Import as variables

1. Open the Figma file, then **Plugins** and **Export/Import Variables**.
2. Go to the **Import** tab.
3. Import the files from the `native-variables/` folder of your choice:
   - For one collection, choose `dfh-unified.json`. It makes a collection called Design For Humans with one mode: light colours, fixed type, and spacing at the large end of its range.
   - For five collections, import `01-color.json`, `02-structure.json`, `03-font-sizing.json`, `04-spacing.json` and `05-pointer.json`, in that order, as each one points at variables in the ones before it.
4. Open **Local variables** and check the collections are there, each grouped into `01 Global`, `02 Semantic` and `03 Component`.

The five collections each do one job:

| Collection | Modes | Holds |
| :--- | :--- | :--- |
| Color | Light, Dark | The palette, every colour role and component colour |
| Structure | One | Fixed spacing, radii, border widths, the fixed type steps and each fluid step's large end, weights and families, shadow sizes and component sizes |
| Font sizing | Fixed, Fluid Large, Compact | Each text role's size and line height in pixels (`body/font-size`, `body/line-height`), and the component tokens that read them. Components that keep one size at every width, like Badge and Chip, stay in Structure |
| Spacing | Fixed, Fluid Large | The spacing roles (`breathe`, `cushion`) and the component tokens that read them |
| Pointer | Touch, Fine | The hit area every control keeps (`spacing/target-min`) and the component tokens that read it, such as a compact Header bar's height |

Every variable carries its CSS name as code syntax, so Dev Mode shows `var(--surface-card)` beside the value. Each one is offered only where it applies: a border colour under strokes, a gap under auto layout. The palette's raw colour steps stay in the file and aren't published: pick a colour role, which follows light and dark.

To set a frame's modes, select it and pick one for each collection under **Appearance** in the right-hand panel. Everything inside follows until a frame inside picks its own. With a `-modes` set, the Color menu switches brand too: course Light, course Dark and so on.

## How fluid sizes work in Figma

On the web, a fluid size slides between two screen widths. Figma can't slide, so each frame picks a size for its type and for its spacing, the way a region of a page picks a sizing class.

Fluid type starts at the fixed size and grows to a larger one on wide screens. A fluid region on a narrow screen is the same as fixed, so Figma needs only its other end: Fluid Large.

| Font sizing | Matches | Use it on |
| :--- | :--- | :--- |
| Fixed | The default | Most frames: interface text keeps one size at every width |
| Fluid Large | `.font-sizing-fluid` on a wide screen | A region that grows with the screen, such as an article or a hero, drawn at desktop width |
| Compact | `.ui-compact` | A dense panel, table or toolbar, at any width |

Spacing grows with the screen whatever the type does, so it has modes of its own:

| Spacing | Matches | Use it on |
| :--- | :--- | :--- |
| Fixed | The small end of the spacing range | A phone-width frame, and any compact frame |
| Fluid Large | The large end | A desktop-width frame |

Pointer matches the targets the product chooses. Touch is the default: every control keeps a 48px hit area, and a bar of controls is never shorter. Fine matches `.fine:targets-sm`, a product that has opted into 32px targets for a mouse, and lets compact bars shrink to match. Leave it on Touch unless the product makes that choice.

So a phone mock-up is Fixed and Fixed, and a desktop one is Fixed type with Fluid Large spacing. An article inside the desktop frame takes Fluid Large type. Container sizes (`.font-sizing-cq`) grow the same way as fluid ones, by the container's width rather than the screen's: give the container's frame the mode it would have at that width.

## 4b. Import with Tokens Studio

1. Install **Tokens Studio for Figma** and open it in your file.
2. Choose **Tools**, then **Load from file**, and pick `tokens-studio/figma-tokens.json` from your theme's folder.
3. Under **Themes**, pick a theme from each group: **Color** (Light or Dark), **Font sizing** (Fixed, Fluid Large or Compact) and **Spacing** (Fixed or Fluid Large) and **Pointer** (Touch or Fine). Theme groups may need Tokens Studio's paid plan. On the free plan, switch the token sets on and off instead: `semantic-light` or `semantic-dark`, one `font-` set, one `spacing-` set and one `pointer-` set.
4. Choose **Styles & Variables**, then **Export styles** to create the text styles and shadow effects, or **Export variables** for variables.

The text styles come from the same type theme as the CSS. Each one reads its role's size, so it follows the Font sizing you pick, and a copy under `compact/` keeps the compact size for files without themes. Line heights are percentages, so they stay right at every size. A variable can't hold a percentage of the size, so if you build a style from the Variables collections instead, bind its line height to the role's `line-height` in Font sizing, which is in pixels for each mode.

## Fonts

Figma finds a font by the name its font menu shows. A web service may give the same font another name for CSS: Adobe Fonts calls Adapter PE `adapter-pe-variable`. In the Token Designer, edit the font and fill in **Name in Figma**, and the export uses that name. The system stacks of the starter theme export as Inter, Georgia and Roboto Mono. The font must be installed, or one Figma offers, for text to show in it.

## Keep Figma up to date

Re-import after a change, with the same plugin and the same files. Variables with the same names are updated in place, so layers bound to them follow. A variable whose token has been removed stays in Figma until you delete it.

## When something looks wrong

- **A colour or size isn't what the CSS shows.** The files are older than the theme. Export them again.
- **A theme is missing from `themes/`.** It hasn't been built: a theme that fails a check isn't exported, and the export names any theme it skipped.
- **An import stops part way.** The plan may not allow that many modes. Use the unified file, or each brand's own folder.
- **Text styles show the wrong font.** Figma doesn't know the font by that name, or it isn't installed. Set its **Name in Figma** in the Token Designer, and install it.
- **An import stops on an unloaded font.** The importer changes a font family without loading the new font, which Figma needs before it can redraw the text that uses it, so a font your file doesn't use yet keeps its old name. Everything else imports. In the Variables panel, under Structure, type the new name into each `font-family` variable that still shows the old one: Figma loads the font itself. The Token Designer's Figma tab lists the names to check. It only happens the first time a font reaches a file.
- **A weight looks wrong.** Weights export as numbers (400, 700) bound to font weight, so Figma picks each font's own style for them, whatever the font calls it. A weight the font doesn't have shows the nearest it does, as a browser would.
