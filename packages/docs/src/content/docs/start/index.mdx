The library is CSS, one icon sprite and no JavaScript. You write ordinary HTML and add its classes. It takes three steps, and none of them needs a build tool or a package manager.

<Screenshot name="real-world" alt="A garden designer's home page built with the library: a header with navigation and a Book a visit button, a hero over a photo of flowers with two buttons and three figures, and a services section below.">A whole page built from the library's components, in its starter theme.</Screenshot>

## 1. Link the styles

Each version of the library is published as one file. Link it in your page head. The newest version is <code>{version}</code>:

<div class="code-block">
  <pre class="code-block__code" tabindex="0" role="group" aria-label="HTML"><code>{link}</code></pre>
</div>

That file holds the reset, the tokens, every component and the utilities, each in its own cascade layer. Put your own CSS in the `site` layer and it wins over the library's components without any fight over specificity, while the utilities still work on it. [Customise](/docs/start/customise/) shows how.

A published version never changes, so your site looks the same until you choose to move. To move up, read what changed in [Releases](/docs/start/releases/), change the number in the link, and check your pages.

**Serving it yourself.** Download the same file and link your own copy, if you'd rather not depend on another domain. To work from the source instead, clone the [repository](https://github.com/PaulCWoods/DFH-Components) and link `packages/css/src/index.css`. It imports each part separately, which is fine while you build; bundle it into one file before you ship.

### Your theme

Out of the box the library wears its starter theme: system fonts and a blue accent. To make it yours, edit a theme in the [Token Designer](/docs/tools/designer/), export its stylesheet and link it after the library. It holds only what your theme changes, and its header comment lists any font links it needs in your page head:

<div class="code-block">
  <pre class="code-block__code" tabindex="0" role="group" aria-label="HTML"><code>{themed}</code></pre>
</div>

[Working with the Token Designer](/docs/tools/designer/) covers the whole round trip, and [Themes and sub-brands](/docs/start/themes/) how themes work.

## 2. Add the icons

Each version publishes its icon sprite beside its CSS, at <code>{icons}</code>. Download it and serve it from your own site: a browser only draws sprite icons from the page's own domain. Then point at a symbol by name:

```html
<svg class="icon" width="1em" height="1em" aria-hidden="true" focusable="false">
  <use href="/icons.svg#search"/>
</svg>
```

The icon takes its size and colour from the text around it. Icons take [Lucide](https://lucide.dev)'s names, so you can find one by name there; see [Icon](/docs/components/atoms/icon-icon-box/) for the rest. Keep the comment at the top of the file: it holds the licence notices the icons come with.

## 3. Build a page

The bones of a page are native landmarks. A [Skip Link](/docs/components/atoms/skip-link/) comes first, then the [Header](/docs/components/organisms/header/), the main content and the [Footer](/docs/components/organisms/footer/). The [App Shell](/docs/components/layout/app-shell/) keeps the Footer at the bottom of a short page. This one serves its own copies of the files:

```html
<!doctype html>
<html lang="en-GB">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Woodland Plants</title>
    <link rel="stylesheet" href="/css/dfh-components.css" />
  </head>
  <body class="app">
    <a href="#main" class="skip-link">Skip to main content</a>
    <header class="header">
      <div class="header__bar">
        <a href="/" class="brand"><span class="brand__name">Woodland Plants</span></a>
      </div>
    </header>
    <main id="main" class="main">
      <div class="wrapper stack">
        <h1 class="title">Ferns for shade</h1>
        <p class="text">Everything here grows in part or full shade.</p>
        <div class="cluster">
          <a href="/plants/" class="button button--strong button--accent">See the plants</a>
        </div>
      </div>
    </main>
    <footer class="footer">
      <div class="footer__bar">
        <p class="small-text text-muted">Woodland Plants</p>
      </div>
    </footer>
  </body>
</html>
```

From there, each part is a class or two on the element you'd use anyway. Here is a [Card](/docs/components/molecules/card/) holding a heading, some text and a [Button](/docs/components/atoms/button/):

```html live width=md
<article class="card">
  <header class="card__header">
    <h2 class="card__title heading">Hart's tongue fern</h2>
  </header>
  <div class="card__body">
    <p class="text">Evergreen, and happy in a damp, shady corner.</p>
  </div>
  <footer class="card__footer">
    <button type="button" class="button">Add to border</button>
  </footer>
</article>
```

## What you get without asking

- **Light and dark.** Colours follow the visitor's setting. To fix one, add `.color-scheme-light` or `.color-scheme-dark` to the page or to a region.
- **System fonts.** The library's CSS loads no fonts and makes no requests of its own. To use your own, give your theme its fonts in the [Token Designer](/docs/tools/designer/), and add the font links its stylesheet lists to your page head.
- **Touch-sized targets.** Controls have a 48px target unless your product opts into smaller ones for a fine pointer.

## Browsers

Anything a component needs to work uses features that are [Baseline widely available](https://web.dev/baseline). Newer features are for polish, or come with a working fallback.
